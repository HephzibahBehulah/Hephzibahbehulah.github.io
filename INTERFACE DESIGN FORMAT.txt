INTERFACE DESIGN FORMAT
VoltPro Engineering Tools — ElectCAD Reference
==============================================

PURPOSE
ElectCAD is the visual reference for the VoltPro engineering workspace. The other tools should share its recognizable shell and interaction patterns while keeping their own real canvas, commands, components, and engineering rules. This is a reusable product standard, not a request to copy ElectCAD’s schematic canvas into every tool.

REFERENCE IMPLEMENTATION
Live reference: https://engineering.hephzibahbehulah.com/electcad
Source: apps/engineering/voltpro-electcad/App.tsx and apps/engineering/voltpro-electcad/styles.css
Shared routes and shell: apps/voltpro-engineering-source/workspace-shell.html, workspace-shell.js, workspace-shell.css

1. SHARED WORKSPACE SHELL
- Use one shared top command bar, a narrow left tool/panel rail, the largest possible central canvas, a right workspace dock, and one bottom cross-tool navigation bar.
- Keep the top command bar to one row. Put project identity/actions, the tool’s menus and editing controls, zoom controls where relevant, and shared workspace utilities in that row. Do not stack duplicate application headers or create a second top toolbar.
- Keep shared utilities in familiar positions: My workspace, language, theme, About/readiness, and account. Preserve their current working behavior.
- Bottom navigation links to Simulator, PLC, ElectCAD, Engineering Tools, Breadboard, and Electrical, with the current tool marked active.
- Each tool keeps its own menu contents and editing actions. Common shell placement stays consistent.
- At narrow widths, compact optional branding and spacing first. If necessary, scroll the single toolbar intentionally. Never clip or silently hide essential controls.

2. ELECTCAD VISUAL REFERENCE
- Dark charcoal workspace, fine grid, subtle borders, cool light text, and warm VoltPro orange highlights.
- Compact engineering controls with restrained rounding and clear hover, focus, selected, pressed, and disabled states.
- Technical labels may use monospaced type; normal interface text remains readable.
- Preserve dark/light themes and ensure symbols, text, menus, wires, and selection states remain legible in both.
- Reuse the VoltPro and Hephzibah Behulah identity consistently. Do not add a duplicate brand header.

3. SHARED LAYOUT BEHAVIOR
- Left rail buttons open clear contextual panels for tools, pages, search, or component libraries. Panels may overlay part of the canvas; they should not permanently steal its working area.
- The right dock holds the selected object’s properties and tool-specific results, diagnostics, or simulation output. Provide a clear collapse/reveal control and usable scrolling.
- Keep the canvas central. Preserve editor state and project data when panels open, close, or the route changes.
- Use descriptive accessible names for icon-only controls, keyboard-visible focus, and accurate expanded/pressed states. Menus and popovers must remain above the canvas and not be clipped.

4. TOOL-SPECIFIC CANVASES
Keep the shared shell, but use the correct work surface for each job:
- ElectCAD: electrical schematic drawing with real symbols, terminals, wires, sheets, and engineering properties.
- PLC: Ladder/control and Function Block programming canvases with PLC devices, terminal or logic connections, tags, and live simulation state.
- Simulator: electronics schematic and measurement workspace with modeled parts, probes, instruments, and simulation results.
- Breadboard: physical-style breadboard canvas with correctly connected hole strips and power rails, board-specific component placement, pin-accurate wiring, and clear labels. Support compatible Breadboard, Schematic, PCB, and Code views when the project contains the required data.
- Electrical: building and industrial installation workspace with measured plans, rooms, distribution/protection equipment, switches, outlets, lights, motors, cables/routes, circuits, and editable device properties.

The supplied motor-control drawing is an industrial power/control wiring schematic: three-phase supply, QF1 protection, KM1 contactor, FR1 overload, stop/start devices, indicator lamps, and motor. It is useful for Electrical and for linking a PLC program to its controlled equipment. It is not itself a Ladder or Function Block program. Keep the electrical drawing and PLC logic as distinct, linkable views.

5. PROJECT PORTABILITY AND MULTI-VIEW WORKFLOW
- Keep a project’s engineering meaning in a structured project model. Canvas views are representations of that model, not screenshots used as the source of truth.
- Offer explicit Open in / Convert to actions for compatible project types. A compatible electronics project may connect schematic, breadboard, PCB, simulation, and code views.
- Use stable component identities, terminal/pin maps, wires/nets, board footprints, simulation models, and target pin mappings where available.
- Preserve the original project and view-specific placement when converting. Do not guess missing mappings or silently discard unsupported parts; show a reviewable mapping or warning and let the user decide.
- Building installation plans, electronics circuits, and PLC logic have different domain data. Connect them intentionally through declared devices, tags, terminals, and I/O mappings; do not pretend every object converts directly to every canvas.

6. SAFE IMPLEMENTATION RULES
- Keep existing controls and editor behavior functional. Do not replace working actions with decorative controls or placeholders.
- Reuse shared shell components and style tokens where practical. Keep tool-specific editor logic isolated.
- Avoid unrelated model changes, data migrations, or route changes when making a layout update.
- Verify desktop and narrow layouts, menu opening, panel open/close, selection, save/import/export, simulation entry points, and route navigation before considering a tool aligned.
- Treat warnings and readiness disclosures as visible product information; do not imply standards or safety validation that the tool has not performed.

This format preserves ElectCAD as the reference shell while allowing each VoltPro tool to keep a domain-correct canvas and commands. It describes intended reuse; it does not claim that every cross-tool conversion or view already exists.
